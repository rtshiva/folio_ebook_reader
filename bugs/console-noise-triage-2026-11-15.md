# Console noise triage — 2026-11-15 (reported during Card 2 acceptance)

Context: errors seen in devtools while acceptance-testing the battery-saver build.
**None were related to Cards 1-2** (keep-awake / battery degrade): the power pipeline was
CDP-probe-verified twice with zero console noise; the `file:///F:/Siva_f/...` URLs proved
that console session was `src/index.html` loaded from disk (origin `null`).

**RESOLUTION STATUS (2026-11-15, second pass): 1, 2 fixed; 5 superseded by a real bug fix
(snapshot URL absolutization); 6 VERDICT REVISED — the base-uri CSP block is NOT harmless;
new broken-image tile feature added.**

## Items

1. **CORS block: `file:///.../spine-ornament.svg` from origin 'null'** — **FIXED.**
   CSS `mask-image` fetches run in CORS mode; from a `file://` page every fetch is
   origin-null. The three mask-referenced ornament SVGs (corner-acanthus, medallion-maroon,
   spine-ornament — 6 refs) are now inlined as `data:image/svg+xml;base64` (~9 KB); damask
   stays file-referenced (plain background-image, no CORS mode). Computed-style probe
   confirms masks resolve to data: URIs.

2. **epub.min.js `injectIdentifier` 'packaging' TypeErrors (repeating)** — **FIXED (app-side).**
   Root cause chain proven in vendored source: each Rendition registers `injectIdentifier`
   on the SHARED `book.spine.hooks.content`; `Rendition.destroy()` nulls `this.book` without
   deregistering; Spine passes its hooks object to every Section, and `Section.render`
   triggers those hooks — every section render fires ALL dead renditions' hooks.
   `Hooks.trigger` logs sync throws via `console.log` (log-level, not error). Fix:
   `recreateRendition()` clears `book.spine.hooks.content` after destroy (nothing else
   registers there; serialize hooks are a separate object; closeBook was already clean via
   `book.destroy()`). Probe: hook count stays 1 through recreations (was 4→5→6→7 — the open
   flow itself recreates 3×).

3. **`Blocked script execution in 'about:srcdoc' … 'allow-scripts'` (×20+)** — **by design,
   accepted.** Snapshot/covers iframes are deliberately `sandbox='allow-same-origin'`
   (index.html:7074/7211). The messages are the sandbox working.

4. **`[Intervention] Images loaded lazily…`** — informational WebView2 notice. No action.

5. **`image_rsrc9ZV.jpg ERR_FILE_NOT_FOUND`** — **book defect + exposed a REAL app bug.**
   `image_rsrc` is generated by NOTHING in this codebase (app/Rust/vendored libs all
   ruled out) — the name is authored inside the user's book file, pointing at an image
   missing from the package. However, chasing it exposed item 6 (below), which made
   relative book images fail on every snapshot replay — fixed in the same batch.

6. **`base-uri 'self'` CSP blocks epub.js `<base>` per chapter — VERDICT REVISED.**
   First pass called it harmless (live folio-cache docs resolve relatives against their
   document URL). The tile-probe investigation proved it breaks SNAPSHOT replays:
   replay docs are `about:srcdoc` with no applicable base, so relative resource URLs
   resolved against the app origin (`http://tauri.localhost/pix.png`) → silent 404s on
   every page-turn replay. **FIXED without weakening CSP**: `onContent`'s capture now
   absolutizes relative `img[src]` against the live doc's `baseURI` (the folio-cache URL)
   before serialization — probe shows replay docs carrying absolute srcs and images
   loading (`nw=1`). The 404 for the genuinely-missing book image remains (correct).

7. **NEW: graceful broken-image tiles.** Books with missing resources now render a styled
   tile (`role=img`, "Image unavailable: <alt/src>", rect-sized, theme-following via
   currentColor) instead of the raw broken glyph — implemented in `installBrokenImageTiles`
   (onContent hook). **Critical timing subtlety the probe caught:** rendering docs are
   about:srcdoc, so relative srcs fail BEFORE epub.js's async resource substitution rewrites
   them to working URLs — an immediate swap would permanently tile images about to load
   (first implementation did exactly that: the GOOD image got tiled). Final version waits
   600ms after each error and swaps only if the src is unchanged and the image still fails.

## Probe lessons (for future sessions)
- epub.js `Hooks.trigger` logs hook throws at console.LOG level — CDP captures filtering
  `type==='error'` see nothing.
- Chapter iframes are script-blocked sandboxes: `frame.evaluate` hangs; reach chapter DOM
  from the main page via `iframe.contentDocument` (allow-same-origin).
- Frames detach constantly (pageCache swaps) — retry loops with re-acquisition.
- epub.js `adjustImages` strips img width/height attributes; use layout rects.
- `zipStore` (helpers.mjs) builds test epubs with binary content (exported now).
